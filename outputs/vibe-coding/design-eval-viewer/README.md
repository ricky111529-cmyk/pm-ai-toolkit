# 디자인 평가 뷰어

AI가 만든 결과물을 **전 페이지 썸네일 + 맥락(원래 요청·만족도 점수·코멘트)**과 함께 펼쳐 보고, 그 자리에서 **페이지 단위로** 평가를 남기는 단일 HTML 앱입니다.

> **공개판입니다. UI는 일본어입니다.** 사내에서 만든 것에서 데이터 경로와 쿼리를 제거하고, 샘플 데이터로 동작을 볼 수 있게 바꿨습니다.
> 자세한 배경과 설계 판단은 [`../llm-qa-pipeline/PORTFOLIO.md`](../llm-qa-pipeline/PORTFOLIO.md)의 "그래서 다음에 만든 것"에 있습니다.

## 열어보기

```bash
python3 -m http.server 4941 --directory .
```

`http://localhost:4941` → **サンプル読み込み**(샘플 불러오기). 디자인 12건이 뜨고 필터·검색·라이트박스·평가 작성이 전부 동작합니다.

`file://`로 열면 샘플 로드가 CORS로 막힙니다. 그때는 `demo/sample.csv`를 화면에 끌어다 놓으면 됩니다.

## 왜 이렇게 만들었나

**지표는 "좋았는가"를 기록하지 않습니다.** 못생긴 결과물이 나와도 로그에는 생성 성공으로 남고, 에러율도 퍼널도 울리지 않습니다. 그래서 결과물을 직접 봐야 하는데, 보려면 매번 쿼리를 쓰고 CSV를 받아 URL을 하나씩 열어야 했습니다. SQL을 쓰는 사람만 할 수 있고, 그래서 팀에서 결과물을 실제로 본 사람이 거의 없었습니다.

이 앱은 그 과정을 없앤 것입니다.

### 평가 항목을 미리 정하지 않았습니다

처음엔 평가 카테고리를 13개 만들어 체크박스로 붙였다가 **전부 지우고 자유 메모만 남겼습니다.** 기준을 먼저 박아두면 팀이 그 칸에 맞는 것만 보게 되고, 그 13개는 혼자 상상한 목록이라 맞다는 근거가 없었기 때문입니다. 실제 문제가 그 밖에 있으면 영영 안 보입니다.

대신 메모를 **ボディ / マスター / その他**(바디·마스터 컴포넌트·그 외) 세 칸으로만 나눴습니다. 어느 층위의 문제인지는 나중에 모아 세려면 필요하고, 그건 상상이 아니라 제품 구조에서 나오는 구분이라서요. 세 칸을 다 채울 필요는 없습니다.

### 판정 단위는 결과물이 아니라 페이지입니다

"이 결과물이 나쁘다"는 고칠 수 없지만 "3페이지에서 소제목이 줄바꿈된다"는 고칠 수 있습니다.

## 기술적으로 볼 만한 것

| | |
|---|---|
| **큰 압축 파일을 브라우저에서 열기** | `DecompressionStream('gzip')`으로 스트리밍 해제. 진행률 분모는 **압축 해제 전** 바이트를 세서 서버 압축 설정과 무관하게 정확합니다 |
| **점진 렌더링** | 최신 날짜부터 읽어 한 덩어리를 읽는 즉시 화면을 띄우고 나머지는 뒤에서 붙입니다. 보는 동안 필터·검색·스크롤이 유지됩니다 |
| **탭이 숨겨져도 멈추지 않음** | 양보에 `requestAnimationFrame`을 쓰면 숨은 탭에서 발화하지 않아 로딩이 멈춥니다. `setTimeout`은 1초로 throttle됩니다. 그래서 `MessageChannel`을 씁니다 |
| **컬럼 자동 분류** | 값 종류가 2~120개면 드롭다운 필터, 그보다 많으면(계정 등) **검색형 드롭다운**, 긴 텍스트는 본문으로. 컬럼 계약을 강제하지 않습니다 |
| **선택 상태를 DOM에 두지 않음** | 값이 많은 컬럼은 앞 300개만 그리므로, 화면에 없는 체크박스에서 선택을 되살릴 수 없습니다. 그래서 선택의 원천은 별도 객체입니다 |
| **의존성 0** | `index.html` 한 파일. 빌드 없음 |

## CSV 계약

필수는 두 개뿐입니다.

| 컬럼 | |
|---|---|
| `design_id` | 결과물 식별자 (같은 값이면 한 카드로 묶임) |
| `page_url` | 페이지 이미지 URL |

나머지는 있으면 쓰고 없으면 넘어갑니다 — `ページ順` `ページ数` `生成日` `生成時刻` `NPS` `NPS区分` `コメント` `プロンプト` `国` `ユーザー種別` `account_id` 등. **속성 컬럼은 무엇을 넣어도 됩니다.** 값 종류를 보고 필터가 자동으로 생깁니다.

`プロンプト`·`コメント`처럼 긴 텍스트는 **첫 페이지 행에만** 넣습니다(중복 제거).

전체 예시는 [`demo/sample.csv`](demo/sample.csv)에 있습니다.

## 평가를 어디에 모으나

`apps-script.gs`를 구글 시트의 Apps Script에 붙이고 웹 앱으로 배포한 뒤, 그 `/exec` 주소를 `index.html`의 `SHEET_ENDPOINT`에 넣으면 팀 전원의 평가가 시트 한 곳에 쌓입니다. 작성자는 브라우저가 보낸 값이 아니라 **서버가 구글 로그인 계정에서 정하므로** 위조할 수 없습니다.

**비워두면**(공개판 기본값) 시트로 보내지 않고 클립보드에 시트 한 줄(TSV)을 복사합니다. 설치 없이 UI만 먼저 써볼 수 있습니다.

### 겪은 것

- `fetch`로 보내면 안 됩니다. Apps Script를 도메인 제한으로 배포하면 CORS에 막힙니다. **HTML form 전송**은 구글 세션 쿠키를 실어 보내서 통과합니다
- 그 응답은 읽을 수 없고 iframe으로 보여줄 수도 없습니다(구글이 `X-Frame-Options`로 자기 페이지의 iframe 표시를 막습니다)
- `LockService`는 쓰지 않습니다. 동시 저장이 몰리면 20초 타임아웃으로 저장이 통째로 실패했습니다. `appendRow`는 한 행을 원자적으로 붙이고, `=IMAGE(...)` 수식은 문자열로 같이 넣으면 되므로 잠금이 필요 없습니다

## 공개판에서 제거한 것

사내 데이터 볼륨에서 파일을 받아오는 경로, 실제 SQL(사내 테이블 구조), 배포·인프라 설정, 데이터 규모 수치. 스크립트가 참조하는 요소는 빈 자리로 남겨 두었습니다.
