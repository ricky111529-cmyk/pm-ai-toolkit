01
オンボーディングVoC×ログ分析仮説検証継続利用

初回体験の阻害要因を特定し、エラー率を13.4%から5.1%に改善。

13.4% → 5.1%初回生成failure率（改善後 約20h・14,000+セッションで検証）
Background / 背景
ユーザーの声(VoC)を追う中で、「AIスライド生成の最初の入力でAIが応答を生成できず、そのまま離脱する」ユーザーが一定数いることを確認。初回体験が定着に直結していた。
Hypothesis / 仮説
失敗率を下げれば → 満足度が上がり → retentionが向上するはずだ。
Approach / アプローチ
約3万件を分析し、失敗原因を3つのroute（聞き返し／不適切な拒否／空応答）に分類。優先度を共有し、緊急バグはエンジニアへ、残りは企画メンバーと議論。分析基盤はAIとのペア開発で構築。
Result / 結果
初回失敗を 13.4% → 5.1%（route別すべて改善）。定性的にも失敗入力の大半が正常処理へ。継続利用の土台をつくった（満足度・リテンションへの影響は今後の計測対象）。
Learning / 学び
分析要件の定義から改善後の検証までを主導した経験。
02
UXリサーチProduct Discoveryオーナーシップチーム連携

ユーザー理解の不足を課題として提起し、UXリサーチを自ら立ち上げた。

Background / 背景
PMとして企画を出しても通らないことがあり、理由を掘るとデータ・明確なユーザー仮説・説得力が足りていなかった。根本は「チームがユーザーを深く理解できていない」こと。
Hypothesis / 仮説
良い企画の前提は“正確なユーザー理解”。体系的に理解する仕組みをつくれば、企画の精度も説得力も上がる。
Approach / アプローチ
1on1で課題を提起 → チームも共感し、データの多い韓国ユーザーをまず見る方向に整列。4つの問い（誰を／課題は何か／解決できているか／どう解決すべきか）を軸に、インタビュー設計・定性分析のフレームワークを整備。
Result / 結果
現在進行中。これは指示ではなく、自分が必要だと感じて立ち上げた取り組みで、問題定義からチームを動かすところまでを自分で行った。
Learning / 学び
課題は与えられるものではなく、自分で定義してチームを動かせるものだと実感した。
03
Product OperationsAI活用評価設計業務効率化

AI生成物をチームで評価できる環境を設計・実装。

公開デモを触ってみる →

Background / 背景
AI生成物の品質を確認するには、データを取得し、URLを一つずつ開く必要があった。手間がかかるため、チームで実物を見られる人がほとんどいなかった。
Approach / アプローチ
生成物の全ページと、ユーザーの依頼・満足度評価を一画面で確認し、ページ単位でコメントを残せるビューアをAIとのペア開発で実装。評価項目は先に固定せず、コンポーネント層の3区分＋自由メモにした（先に枠を決めると、枠の外の問題が見えなくなるため）。
Result / 結果
チームに公開し、ページ単位の評価が一つのシートに蓄積される運用を開始。SQLを使わなくても、誰でも生成物を確認できるようになった。
Learning / 学び
LLM QAの失敗から順序を反転——自動評価を先につくらず、人の判断を先に集める。蓄積した評価から基準を導き、その後に自動化する。
