# 프롬프트: 무한루프 QA

> POC·문서·코드를 평균 98점이 될 때까지 자동으로 개선하는 에이전트 루프.
> 구현 완료 후 "구멍 찾기" 단계에서 사용합니다.

---

## 언제 쓰나

- POC 완성 후 실제 사용 시 문제가 생길 것 같을 때
- 문서·정책서 완성 후 누락이 없는지 검증할 때
- 코드 리팩토링 후 품질 보장이 필요할 때

---

## 프롬프트 템플릿

```
에이전트 5개를 만들어서 아래 업무를 수행하고,
평균 점수가 98점이 될 때까지 QA를 무한으로 돌아.

에이전트 1 — 읽고 계획 세우기
[대상 파일/결과물] 전체를 읽고, 현재 상태를 파악한 뒤
개선 계획을 수립해. 에이전트 3·4·5의 피드백이 있으면 반영해서 계획 업데이트.

에이전트 2 — 계획에 따라 구현·작성
에이전트 1의 계획을 그대로 실행해.
코드 수정, 문서 보완, 내용 추가 등 실제 결과물을 만들어.

에이전트 3·4·5 — 냉정한 평가
새로운 관점으로 결과물을 평가해. 각자 다른 기준으로:
- 에이전트 3: 사용성·명확성 (처음 보는 사람이 이해할 수 있는가?)
- 에이전트 4: 완결성·누락 (빠진 내용·예외 케이스가 없는가?)
- 에이전트 5: 일관성·퀄리티 (용어·스타일·구조가 통일됐는가?)

각 항목 0~100점으로 채점하고, 평균이 98점 미만이면
구체적인 피드백을 에이전트 1에게 전달해서 루프를 계속해.
평균 98점 이상이면 루프 종료 후 최종 결과 보고.

대상: [파일 경로 또는 작업 내용]
```

---

## 루프 종료 기준

- 에이전트 3·4·5의 평균 점수 **98점 이상**
- 또는 사용자가 "충분해, 여기서 멈춰"라고 명시

---

## 주의사항

- 루프 횟수에 제한 없음 — 토큰 비용 발생 가능
- 중요한 작업에만 사용 (단순 문서는 3회 루프로 충분)
- **마지막은 반드시 사람이 검수** — AI 평가에만 의존 금지
- 루프 중 파일 덮어쓰기가 발생하므로 Git 커밋 후 시작할 것

---

## 비용 절약 변형: 3에이전트 버전

빠른 QA가 필요할 때:

```
에이전트 3개로 QA를 돌아. 목표 점수 95점.

에이전트 1: 읽고 계획
에이전트 2: 실행
에이전트 3: 평가 + 피드백 → 에이전트 1로 전달

[대상 파일 경로]
```
